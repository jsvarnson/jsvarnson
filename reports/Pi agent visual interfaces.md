# Run Pi Through Zed, Then Restyle Freely

For someone who never wants to touch a terminal, the best way to use the pi coding agent today (Mario Zechner's harness, now maintained by Earendil as `earendil-works/pi`) is the **Zed editor running Pi as an "external agent" from Zed's built-in ACP Registry**. You add it with a few clicks, you get a polished chat panel, and Zed has a mature theme system: installable themes, color overrides, a Theme Builder and separate font settings for the agent panel. If you want deeper control over the look than Zed allows (your own colors, panels and layout, down to the CSS), the second pick is **agegr/pi-web**, the most popular community web interface (about 7,500 GitHub stars). It runs in your browser, and because it is ordinary open-source web code, an AI assistant can restyle it for you. A desktop app such as Percho or pi-gui comes third, for people who want an app icon in the dock. Two facts frame every option. First, **pi has no official graphical app**: everything visual is a community project ([how-pi-works.md](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/how-pi-works.md)). Second, **almost every route needs one short install session**: you put Node.js on the computer with a normal installer, paste one command, and sign in once. After that, everything can be point-and-click. The Claude Code "mods" probably failed for structural reasons. Mods add widgets inside Claude Code's own interface; they cannot reskin it. They also skip themselves silently in many common situations, and a mod written in a cloud session disappears when that session ends.

## Pi is built for terminals, so every visual front end is borrowed

Pi describes itself as "a minimal, extensible agent harness that you can make your own" ([README](https://github.com/earendil-works/pi/blob/main/README.md)). Some names have changed since older guides were written. The GitHub repository moved from `badlogic/pi-mono` to `earendil-works/pi`, the install package is now `@earendil-works/pi-coding-agent` instead of `@mariozechner/...`, and the website is pi.dev ([coding-agent CHANGELOG](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/CHANGELOG.md)). Pi is mature and popular. **Version 1.0 shipped on 1 October 2026, and 1.3.0 is current as of 15 October 2026** ([CHANGELOG](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/CHANGELOG.md)). The 1.0 release reached #1 on Hacker News ([trendingtopics.eu](https://www.trendingtopics.eu/pi-1-0-earendil-en/)).

The catch for you is that pi's own visual customization lives entirely in the terminal. Inside the terminal it is very flexible: JSON color themes, add-ons that replace the header, footer and text box, pop-up overlays, and even games ([themes.md](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/themes.md); [tui.md](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/tui.md)). Graphical apps don't use that screen, though. They talk to pi through a behind-the-scenes channel called "RPC mode", and in that mode **pi's themes and custom screen elements switch off**. Theme switching fails with "Theme switching not supported in RPC mode", and custom components draw nothing ([rpc-extension-ui.md](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc-extension-ui.md)). The only things that come through are plain text, simple dialog boxes and status messages. **Whatever app you use to see pi is responsible for the look, and pi's own theme files won't help you.** So the useful question is which app offers the deepest styling that you can reach without coding.

Earendil has also stepped back from building graphical apps. The old official `pi-web-ui` package was a toolkit for developers, not a ready-made app. It was removed from the project in May 2026 and has been frozen at version 0.75.3 since then ([CHANGELOG](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/CHANGELOG.md); [npm](https://www.npmjs.com/package/@earendil-works/pi-web-ui)). An experimental official remote client and server were added in August and removed again in October 2026 ([CHANGELOG](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/CHANGELOG.md)). Don't wait for an official app, and avoid any guide that tells you to install the old `pi-web-ui` package.

## The options compared on effort, maturity and how far you can restyle

Every option below except the "build your own" path relies on pi itself being installed. The table ranks them for your situation.

| Rank | Option | What you see | One-time setup | Maturity | How far you can restyle |
|---|---|---|---|---|---|
| 1 | **Zed + Pi from the ACP Registry** | Pi as a chat panel inside a modern editor | Install Node.js and pi; install Zed; pick Pi from the registry | High. Zed is a mature editor, and the main adapter, svkozak/pi-acp, has 736 stars and is actively updated | Many themes, per-color overrides, Theme Builder, agent-panel fonts; no CSS |
| 2 | **agegr/pi-web** (browser) | Full web app: sessions, chat, model settings, file preview | Node.js and pi, then one launch command (can be turned into a double-click file) | Highest of the community GUIs: about 7,500 stars, 28 open issues | Unlimited if you, or an AI helping you, restyle its code |
| 3 | **Desktop apps** (Percho, pi-gui, pi-app) | A regular app window | Download the installer; most also need pi installed | Medium: young, mostly single-maintainer projects (pi-gui 1,271 stars) | Percho: light/dark/system plus a custom background image |
| 4 | **Build or fork your own UI with AI** | Exactly what you design | Highest: you run a small local server and maintain it | Depends on you | Total |
| — | VS Code extensions | Sidebar chat inside VS Code | VS Code, pi, and an extension | Low: most have fewer than 50 stars; the popular one is still a terminal | VS Code themes, which chat panels often ignore |
| — | Orca, AionUi, Obsidian | Multi-agent or note-taking hosts | Varies | Orca is large; pi support in the others is unconfirmed | AionUi reportedly allows custom CSS (unverified) |

**Zed comes first because it is the only route that is both reliable and installed without a terminal.** Zed has an official "Pi – ACP Agent" page and recommends installing Pi from the registry inside the editor ([Zed: Pi ACP Agent](https://zed.dev/acp/agent/pi)). ACP (Agent Client Protocol) is a shared standard that lets an editor show an outside agent's conversation. The adapter starts pi in the background and passes messages back and forth ([svkozak/pi-acp](https://github.com/svkozak/pi-acp)). Zed's theming is the best documented of all the options. You can install themes from its extension store, change single colors with `theme_overrides`, design and export a full theme with the Theme Builder, and follow your system's light or dark mode ([Zed docs: Themes](https://zed.dev/docs/themes.md)). The agent panel also has its own text size and font settings (`agent_ui_font_size`, `agent_ui_font_family`) ([Zed docs: Visual customization](https://zed.dev/docs/visual-customization)). It has limits. Zed uses structured theme files, not free-form CSS, and nobody has confirmed that every element of the Pi chat panel follows your overrides. The adapter has **89 open issues**, and several forks exist that add missing features ([GitHub](https://github.com/svkozak/pi-acp)), so you should expect some rough edges.

**agegr/pi-web is second, and it is the right choice if deep visual control matters more than polish.** It is by far the most popular pi interface, with **7,516 stars and 1,135 forks** ([GitHub](https://github.com/agegr/pi-web)). It opens in your browser at a local address, lets you browse, pin, rename and export sessions, shows the agent's thinking and tool use as it happens, and lets you sign in or paste an API key under Settings → Models. It saves everything in pi's normal format, so it stays compatible with any other pi tool ([instagit summary](https://instagit.com/agegr/pi-web/how-to-build-the-agegr-pi-web-project/)). Being a web page is what makes it restylable: an AI assistant can edit a copy's colors, fonts and layout directly, which is the closest any pi option comes to the "make it look exactly how I want" promise of mods. The cost is that it needs a command to start. By default it only listens to your own computer, and you can add a password with `PI_WEB_PASSWORD` ([instagit summary](https://instagit.com/agegr/pi-web/what-is-the-purpose-of-the-pi-web-repository/)). One reviewer warns that exposing a pi web interface on an open network "hands a shell to whoever finds it" ([Botmonster](https://botmonster.com/coding/pi-web-ui-for-pi-coding-agent/)), so keep it on your own machine.

**Desktop apps are third: easiest to start, weakest on maturity.** pi-gui (Electron, 1,271 stars) is the most widely used. Percho (452 stars) runs pi's engine inside the app, shares settings and sessions with regular pi, and offers **light/dark/system themes plus a custom background image with dimming** ([Percho](https://github.com/Jaxton07/percho); [wiki](https://github.com/Jaxton07/percho/wiki)). pi-app (379 stars) adds Git review and works on Windows, macOS and Linux ([pi-app](https://github.com/justhil/pi-app)). They are all between one and eight months old, they are mostly built by one person each, and none documents user CSS ([pi-gui](https://github.com/minghinmatthewlam/pi-gui)). For Mac users there is also Pie, a native Mac app ([Pie](https://github.com/hieunc229/Pie)).

**Avoid these for now.** The most popular VS Code extension, pithings/pi-vscode (186 stars), simply shows pi's terminal inside VS Code ([GitHub](https://github.com/pithings/pi-vscode)), and an automated scan of its Open VSX listing gave it a high risk score ([riskyplugins.com](https://riskyplugins.com/extension/5c63a580-2ed4-52a4-bec0-9f6d45251246/openvsx)). The VS Code sidebar-chat alternatives have fewer than 50 stars each ([Zetaphor](https://github.com/Zetaphor/pi-vscode-extension)). VS Code chat panels are also known to ignore your theme colors ([claudeissues #45841](https://claudeissues.com/issue/45841-vscode-extension-chat-panel-inline-code-and-code-blocks-have-no-background-ignor)). Orca is large (about 98,000 stars) and lists Pi as a built-in agent, but **it turns off pi's confirmation prompts by default** ([Orca docs](https://www.onorca.dev/docs/agents/supported)). That matters because pi has no built-in permission system to begin with ([README](https://github.com/earendil-works/pi/blob/main/README.md)). AionUi reportedly lets you paste custom CSS in Settings → Display, but that claim comes from an auto-generated guide ([instagit](https://instagit.com/iofficeai/aionui/aionui-customize-ui-user-css-injection/)), and pi support in AionUi is only implied by another project built on it ([mu](https://github.com/qybaihe/mu)).

## One install session cannot be avoided, but it takes about ten minutes

No researcher found a pi installer that works with clicks alone. Pi needs Node.js version 22.19 or newer ([README](https://github.com/earendil-works/pi/blob/main/README.md)), and the Zed adapter and pi-web both need Node 22+ too ([pi-acp](https://pi.dev/packages/@geohar/pi-acp)). Some desktop apps may bundle pi, but that is unverified. gustavonline's Pi Desktop, for example, shows install instructions when pi is missing ([GitHub](https://github.com/gustavonline/pi-desktop)). The least painful path is to treat the terminal as a one-time chore, like plugging in a printer. You open it once, paste two lines, and close it for good.

| Step | What to do | Notes |
|---|---|---|
| 1 | Download and run the **Node.js "LTS" installer** from nodejs.org. Click through it the way you would install any app. | This is a normal installer with no typing. |
| 2 | Open the terminal once. On Mac: press Cmd+Space, type "Terminal" and press Enter. On Windows: Start menu, type "PowerShell" and press Enter. | This is the only terminal visit. |
| 3 | Paste `npm install -g --ignore-scripts @earendil-works/pi-coding-agent` and press Enter. | This is the official install command ([README](https://github.com/earendil-works/pi/blob/main/README.md)). Windows alternative: `powershell -c "irm https://pi.dev/install.ps1 \| iex"` ([codeagentswarm](https://www.codeagentswarm.com/en/guides/pi-coding-agent-on-windows)). |
| 4 | Type `pi` and press Enter, then type `/login` and follow the prompts to connect your AI account or API key. | Zed expects pi to handle sign-in and model choice ([Zed External Agents](https://zed.dev/docs/ai/external-agents)). |
| 5 | Close the terminal. | You're done with it. |

If you see a guide that uses `@mariozechner/pi-coding-agent`, it is out of date. That name stopped being updated at version 0.73.1 in May 2026 ([CHANGELOG](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/CHANGELOG.md)).

## Getting started with the top two picks

### Pick 1: Zed with Pi, configured visually

| Step | What to do |
|---|---|
| 1 | Finish the one-time install above. |
| 2 | Download Zed from zed.dev and install it like any app. |
| 3 | Open Zed, open the command palette (Cmd+Shift+P on Mac, Ctrl+Shift+P on Windows/Linux), type **`zed: acp registry`**, and choose **Pi** ([pi-acp](https://github.com/svkozak/pi-acp)). |
| 4 | Open the Agent Panel and start a new thread from its new-thread menu, choosing Pi as the agent ([Zed External Agents](https://zed.dev/docs/ai/external-agents.md)). Open a project folder first so pi knows which files it is working on. |
| 5 | Pick a look: browse the extension store for themes, or use the Theme Builder to make your own and export it ([Zed theme extensions](https://zed.dev/docs/preview/extensions/themes.html)). |
| 6 | Fine-tune: in settings, `theme_overrides` changes single colors in your chosen theme, and `agent_ui_font_size` / `agent_ui_font_family` change the chat panel's text ([Zed docs: Themes](https://zed.dev/docs/themes.md); [Visual customization](https://zed.dev/docs/visual-customization)). You can ask pi itself, inside Zed, to make these settings edits for you. |

Sessions started in Zed are saved as ordinary pi sessions, so you can resume them later in any other pi interface ([pi-acp](https://github.com/svkozak/pi-acp)).

### Pick 2: pi-web, restyled to your taste

| Step | What to do |
|---|---|
| 1 | Finish the one-time install above. |
| 2 | Create a small double-click launcher file containing `npx @agegr/pi-web@latest` (on Mac a `.command` file, on Windows a `.bat` file). Ask any AI assistant to write it for you. This hides the terminal in daily use; it is standard practice, though no pi-specific guide covers it. |
| 3 | Double-click the launcher. Your browser opens pi-web at `http://127.0.0.1:30141` ([instagit](https://instagit.com/agegr/pi-web/what-is-the-purpose-of-the-pi-web-repository/)). |
| 4 | Go to Settings → Models and sign in or paste your API key ([instagit](https://instagit.com/agegr/pi-web/how-to-build-the-agegr-pi-web-project/)). |
| 5 | For a custom look, ask an AI coding assistant (pi itself works) to make a personal copy of pi-web and change its colors, fonts and panel layout. Then point your launcher at that copy. |

Step 5 has a cost. A personal copy doesn't pick up pi-web's updates automatically. Pi has also changed its internal message format before: a breaking change shipped in version 0.84 in August 2026 ([CHANGELOG](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/CHANGELOG.md)). Keep your changes to looks only (colors, fonts, spacing), so that redoing them on a newer version stays easy. Writing your own interface from scratch on pi's RPC channel is possible, since it is documented and comes with ready-made helper code ([rpc.md](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc.md)). But it means running and maintaining your own little server that can run commands on your computer, which is more risk than restyling an existing app.

## Claude Code mods failed because they decorate the interface rather than reskin it

Claude Code mods are small programs that run inside Claude Code and add pieces to it: a side pane, a band above the prompt, status text, pop-up messages, sounds and new slash commands ([Claude Code docs: Mods overview](https://code.claude.com/docs/en/plugins/mods/overview)). They can only draw with a fixed set of building blocks, colored from a fixed list of theme names. **They cannot restyle Claude Code's own window.** If you hoped mods would change the overall look, they were the wrong tool from the start, and themes are a separate setting ([GitHub issue #39369](https://github.com/anthropics/claude-code/issues/39369)).

Even within that scope, mods fail without telling you. Each of the following known causes leaves the mod "looking inert", and the only explanation is hidden in a debug log ([Mods troubleshoot docs](https://code.claude.com/docs/en/plugins/mods/troubleshoot)):

- Claude Code is older than version 2.1.287 ([Mods troubleshoot](https://code.claude.com/docs/en/plugins/mods/troubleshoot.md)).
- The folder was never marked as trusted, or plugins are switched off by safe mode or a settings switch ([Mods troubleshoot](https://code.claude.com/docs/en/plugins/mods/troubleshoot)).
- A mod uses a building block that the current screen can't show, so it is quietly not drawn.
- The mod is used somewhere mods don't draw. Mods work in the terminal version and the desktop app's Code tab. Third-party guides say they don't draw in places like the VS Code panel, WSL sessions or cloud sessions ([explainx.ai](https://www.explainx.ai/blog/claude-code-desktop-app-mods-how-to-install-and-build-guide-2026)), although newer builds list VS Code and mobile as drawing surfaces.

The most likely explanation for you is this: **a mod Claude writes for you in a cloud session lives inside that temporary cloud computer and disappears when the session ends.** It also stays switched off until you answer "Turn on the mods Claude writes in this session?", a question that some setups can't ask at all. Both behaviors come from the plugin-authoring documentation bundled with Claude Code 2.1.304. Without seeing your setup, this is the best-supported guess, not a confirmed diagnosis.

## Conclusion

The search for a "visual pi" really comes down to finding a good host, because pi's own styling stops at the edge of the terminal. Zed is the strongest host because its theme system is mature and documented. The deepest customization comes from a web interface you can restyle freely, and with AI help that path is open to non-programmers. The lesson from the mods experience carries over: real visual freedom comes from owning the layer that draws the screen, not from adding widgets on top of someone else's. That is why a restyled copy of pi-web can deliver what mods promised and couldn't.

Expect the field to change. Every pi interface except the Zed adapter's host is under a year old, most are single-maintainer projects, and Earendil has twice built and then dropped official interface pieces. Pick a tool that stores sessions in pi's normal format (Zed, pi-web and Percho all do). Your history then moves with you when a better app arrives, and the one-time install step stays the only investment you can't take back.
